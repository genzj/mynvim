# CLAUDE.md

Personal Neovim configuration. Lua-based, managed with `lazy.nvim`. All config
lives under the `mynvim` Lua namespace (`lua/mynvim/`).

## Entry point & load order

1. `init.vim` sets `vim.g.mynvim_install` (per-host language/plugin overrides),
   a few GUI options, then `lua require("mynvim")`.
2. `lua/mynvim/init.lua` runs `configs.init()` → `configs.setup()`, then returns
   the user-defined plugins so `lazy.nvim` can pick them up.
3. `lua/mynvim/plugins/init.lua` bootstraps `lazy.nvim` and imports all specs via
   `{ import = "mynvim.plugins" }`.

`mynvim.configs.init` (`lua/mynvim/configs/init.lua`) splits work into:
- `M.init()` — runs immediately: `python`, `options`, `commands`.
- `M.setup()` — schedules the rest (`postplugins`, `highlight`, `vscode`,
  `autocmds`, `keymaps`) on the `VeryLazy` user event.

Because much of the config loads on `VeryLazy`, options set directly from
`init.vim` may be overridden. Override via an `autocmd` on the same event
instead (see README "Override Options").

## Directory layout

- `lua/mynvim/plugins/` — one file per topic (`treesitter.lua`, `completion.lua`,
  `telescope.lua`, `lsp/`, …). Each file **returns a lazy.nvim spec table**
  (a list of plugin specs). 14 spec files total.
- `lua/mynvim/configs/` — non-plugin setup: `options`, `keymaps`, `autocmds`,
  `commands`, `highlight`, `python`, `vscode`, `switches`, `icons`, `install`.
- `lua/mynvim/configs/blends/` — per-language presets (`python`, `rust`,
  `gotmpl`, `cloudformation`) enabled via the `blends` key of `mynvim_install`.
- `lua/mynvim/utils/` — helpers (`keymap`, `vscode`, `telescope` factory on
  `Util`).
- `lua/mynvim/mason/registry/` — custom Mason package registrations.
- `queries/` — Treesitter query overrides (e.g. `gotmpl`).

## Conventions

- **Adding a plugin**: add a spec to the relevant `lua/mynvim/plugins/*.lua`
  file (create a new topic file only if none fits). Follow existing specs:
  lazy-load via `cmd` / `keys` / `ft` / `event`; register which-key groups
  inside a `keys = function()` block with `require("mynvim.utils").keymap.group`;
  keep `version = false` unless pinning is needed. `lazy-lock.json` is
  regenerated by `:Lazy` — don't hand-edit it.
- **Per-host / per-language config** goes through `vim.g.mynvim_install` in
  `init.vim`, which extends `mynvim.configs.install`. Inspect the resolved table
  with `:ShowInstallConfig`. Add LSP servers under `servers`, parsers under
  `treesitter`, Mason tools under `mason`, none-ls sources under `nls`.
- **Indentation is inconsistent** across files (some tabs, some 4 spaces). Match
  the surrounding file rather than reformatting; there is no formatter config.

## Commit conventions

Conventional Commits **plus a gitmoji**, enforced by `commitizen` / `cz-git`
(`.czrc`). Format: `type(scope): :gitmoji: Subject`

- Common types: `feat` (`:sparkles:`), `fix` (`:bug:`).
- Scope is **optional** but must come from the allowlist in `.czrc`:
  `colorscheme, command, completion, dashboard, gui, keymap, lsp, lualine,
  option, plugin, py, statusline, telescope, treesitter, ui, win32, vscode`.
- Examples from history:
  - `feat: :sparkles: Add incremental selection support for treesitter plugin`
  - `fix(treesitter): :bug: start treesitter after loading`

Use the `/commit` skill to build a compliant message.
